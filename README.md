# База знаний QA с ИИ-агентом: шаблон

Шаблон удалённой базы знаний для тестировщика, которая ведётся вместе с ИИ-агентом (Claude Code или похожим). Требования, вопросы, решения, тест-кейсы и справка по продукту хранятся в Markdown-файлах, открываются в **Obsidian** и синхронизируются с закрытым Git-репозиторием (GitLab или GitHub).

Чтобы развернуть базу для нового проекта, достаточно дать агенту ссылку на этот репозиторий и сказать: «разверни базу знаний для проекта X по инструкции AGENT-SETUP.md».

## Зачем

- **Документация не на ноутбуке.** Всё лежит в репозитории, на ноутбуке только рабочая копия из текстовых файлов весом в мегабайты.
- **Всё в одном месте.** И человеку, и агенту не нужно искать по папкам, чатам и загрузкам.
- **Удобный поиск.** Obsidian: поиск по тексту и по полям (статус, задача, платформа), ссылки между документами, сводные таблицы.
- **История.** Git хранит каждую правку, у требований и вопросов есть своя история изменений.

## Как работает

1. Пользователь даёт агенту задачу (текст, выгрузку из Jira, документ).
2. Агент сохраняет исходник дословно в `07 Входящие`.
3. Агент **нормализует** требования: одно проверяемое правило — один файл `REQ-NNNN`.
4. Агент **верифицирует** каждое требование по 5 критериям: полнота, однозначность, непротиворечивость, тестируемость, граничные случаи.
5. Неясности становятся **вопросами** (`Q-NNNN`) с вариантами и готовым текстом для отправки. Агент не выбирает вариант сам.
6. Согласованные отличия от ТЗ и ответы «так задумано» становятся **решениями** (`DEC-NNNN`).
7. По требованиям пишутся **тест-кейсы** (`TC-NNNN`), связанные с требованиями.
8. Когда функционал меняется или приходит ответ, агент вносит **правки** и не затирает историю: строка в «Истории изменений», затронутые кейсы помечаются «требует обновления».
9. Obsidian раз в 10 минут сохраняет и отправляет изменения в репозиторий.

Статус «согласовано» ставит только человек. Агент не подписывается как подтвердивший.

## Что внутри

```
vault/                      ← каркас одной базы (копируется под каждый проект)
  00 Главная.md             ← сводка: задачи в работе, открытые вопросы, несогласованные требования…
  Журнал вопросов.md        ← все вопросы по статусам, задачам и адресатам
  Как искать.md             ← горячие клавиши и примеры поиска в Obsidian
  Настройка.md              ← подключение Git и Obsidian (для человека)
  README.md                 ← папки, статусы, платформы
  CLAUDE.md                 ← правила для агента внутри базы
  01 Задачи … 07 Входящие   ← пустые папки
  Шаблоны/                  ← Задача, Требование, Вопрос, Решение, Тест-кейс, Справка
  .obsidian/templates.json  ← папка шаблонов и формат даты
  .gitignore, .gitattributes
skills/                     ← скиллы агента (Claude Code)
  kb-intake/                ← приём задачи: исходник, нормализация, верификация, вопросы
  kb-testcases/             ← тест-кейсы по требованиям
  kb-change/                ← ответы на вопросы, изменения функционала, результаты прогонов
scripts/
  jira-doc-to-text.js       ← выгрузка Jira (Word/.doc) → текст для «Входящих»
  check-links.sh            ← битые ссылки и требования без кейсов
docs/
  why-obsidian-git.md       ← почему не Notion
AGENT-SETUP.md              ← пошаговая инструкция для агента: как развернуть базу
```

## Быстрый старт для человека

1. Дать агенту ссылку на этот репозиторий и попросить развернуть базу для своего проекта (агент действует по [AGENT-SETUP.md](AGENT-SETUP.md)).
2. Создать пустой закрытый репозиторий в GitLab или GitHub и отправить туда базу (команды — в `Настройка.md` внутри базы).
3. Установить Obsidian, открыть папку базы как хранилище, поставить плагины **Dataview** и **Git** (там же, в `Настройка.md`).
4. Прислать агенту первую задачу.

## Несколько проектов

Одна база — один продукт. Если у продукта несколько платформ (приложение, веб, админка, бэкенд), это одна база с полем `platform`, чтобы требования к общему API не дублировались. Разные продукты — разные базы: каждая со своим репозиторием и своим хранилищем в Obsidian. Скиллы общие: базу агент выбирает по разделу «Базы знаний QA» в `CLAUDE.md` рабочей папки.

## Требования

- Git, Obsidian (бесплатный), Node.js — только для скрипта выгрузки Jira.
- Плагины Obsidian: Dataview, Git (из официального каталога).
- Агент с доступом к файлам: Claude Code (скиллы в `skills/` написаны под него), либо другой агент, который читает `CLAUDE.md`.
