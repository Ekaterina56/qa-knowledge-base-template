# База знань QA з ШІ-агентом: шаблон

Шаблон віддаленої бази знань для тестувальника, яку ведуть разом із ШІ-агентом (Claude Code або подібним). Вимоги, питання, рішення, тест-кейси й довідка про продукт зберігаються в Markdown-файлах, відкриваються в **Obsidian** і синхронізуються із закритим Git-репозиторієм (GitLab або GitHub).

Щоб розгорнути базу для нового проєкту, достатньо дати агенту посилання на цей репозиторій і сказати: «розгорни базу знань для проєкту X за інструкцією AGENT-SETUP.md».

## Навіщо

- **Документація не на ноутбуці.** Усе лежить у репозиторії, на ноутбуці лише робоча копія з текстових файлів вагою в мегабайти.
- **Усе в одному місці.** Ні людині, ні агенту не треба шукати по папках, чатах і завантаженнях.
- **Зручний пошук.** Obsidian: пошук по тексту й по полях (статус, задача, платформа), посилання між документами, зведені таблиці.
- **Історія.** Git зберігає кожну правку, у вимог і питань є своя історія змін.

## Як працює

1. Користувач дає агенту задачу (текст, вивантаження з Jira, документ).
2. Агент зберігає джерело дослівно в `07 Вхідні`.
3. Агент **нормалізує** вимоги: одне правило, яке можна перевірити, — один файл `REQ-NNNN`.
4. Агент **верифікує** кожну вимогу за 5 критеріями: повнота, однозначність, несуперечливість, тестованість, граничні випадки.
5. Неясності стають **питаннями** (`Q-NNNN`) з варіантами й готовим текстом для надсилання. Агент не обирає варіант сам.
6. Погоджені відмінності від ТЗ і відповіді «так задумано» стають **рішеннями** (`DEC-NNNN`).
7. За вимогами пишуться **тест-кейси** (`TC-NNNN`), пов'язані з вимогами.
8. Коли функціонал змінюється або надходить відповідь, агент вносить **правки** й не стирає історію: рядок в «Історії змін», зачеплені кейси позначаються «потребує оновлення».
9. Obsidian раз на 10 хвилин зберігає й надсилає зміни в репозиторій.

Статус «погоджено» ставить лише людина. Агент не підписується як той, хто підтвердив.

```

  Журнал питань.md          ← усі питання за статусами, задачами й адресатами
  Як шукати.md              ← гарячі клавіші й приклади пошуку в Obsidian
  Налаштування.md           ← підключення Git і Obsidian (для людини)
  README.md                 ← папки, статуси, платформи
  CLAUDE.md                 ← правила для агента всередині бази
  01 Задачі … 07 Вхідні     ← порожні папки

  kb-intake/                ← приймання задачі: джерело, нормалізація, верифікація, питання
  kb-testcases/             ← тест-кейси за вимогами
  kb-change/                ← відповіді на питання, зміни функціоналу, результати прогонів

docs/
  why-obsidian-git.md       ← чому не Notion
```

## Швидкий старт для людини

1. Дати агенту посилання на цей репозиторій і попросити розгорнути базу для свого проєкту (агент діє за [AGENT-SETUP.md](AGENT-SETUP.md)).
2. Створити порожній закритий репозиторій у GitLab або GitHub і надіслати туди базу (команди — у `Налаштування.md` всередині бази).
3. Встановити Obsidian, відкрити папку бази як сховище, поставити плагіни **Dataview** і **Git** (там само, у `Налаштування.md`).
4. Надіслати агенту першу задачу.

## Кілька проєктів

Одна база — один продукт. Якщо в продукту кілька платформ (застосунок, веб, адмінка, бекенд), це одна база з полем `platform`, щоб вимоги до спільного API не дублювалися. Різні продукти — різні бази: кожна зі своїм репозиторієм і своїм сховищем в Obsidian. Скіли спільні: базу агент обирає за розділом «Бази знань QA» у `CLAUDE.md` робочої папки.

## Що потрібно

- Git, Obsidian (безкоштовний), Node.js — лише для скрипта вивантаження Jira.
- Плагіни Obsidian: Dataview, Git (з офіційного каталогу).
- Агент із доступом до файлів: Claude Code (скіли в `skills/` написані під нього) або інший агент, який читає `CLAUDE.md`.
