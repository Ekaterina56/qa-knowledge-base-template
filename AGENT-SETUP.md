# Інструкція для агента: розгорнути базу знань QA

Користувач дав посилання на цей репозиторій і попросив розгорнути базу знань для проєкту. Дій за кроками. Пиши користувачу його мовою.

## 0. Дізнатися в користувача
Запитати одним повідомленням, якщо це не сказано:
1. **Назва проєкту** (наприклад «Shop App»).
2. **Ключ задач у трекері** (наприклад `SHOP-`), якщо є.
3. **Платформи**: одна чи кілька (застосунок, веб, адмінка, бекенд…).
4. **Де зберігати базу** — папка на комп'ютері. За замовчуванням: поруч із робочою папкою, `kb-<проєкт>`.
5. **Де буде віддалений репозиторій**: GitLab чи GitHub (сам репозиторій створює користувач).

Якщо продуктів кілька — по одній базі на продукт. Платформи одного продукту — одна база.

## 1. Скопіювати каркас
- Склонувати цей репозиторій у тимчасову папку (це завантаження: якщо правила середовища вимагають дозволу — запитати).
- Скопіювати вміст `vault/` у папку бази. Без `.git` шаблону.
- Тимчасову копію шаблону видалити.

## 2. Заповнити заглушки
В усіх файлах бази замінити:

| Заглушка | На що |
|---|---|
| `<<ПРОЄКТ>>` | назва проєкту |
| `<<ПРИКЛАД_ЗАДАЧІ>>` | приклад ключа задачі, наприклад `SHOP-123` |
| `<<ПАПКА_БАЗИ>>` | повний шлях до папки бази |
| `<<АДРЕСА_РЕПОЗИТОРІЮ>>` | адреса віддаленого репозиторію, коли користувач її дасть; до того лишити заглушку |

Платформи:
- **Кілька** — у `README.md` бази лишити таблицю значень `platform` і виправити її під продукт. У шаблонах `platform: []` лишити.
- **Одна** — у `README.md` і `CLAUDE.md` бази видалити розділи про платформи, на `00 Головна.md` видалити розділ «За платформами», із шаблонів — рядок `platform: []` (і `device`, якщо не потрібно).

Перевірити, що заглушок не лишилося: пошук по `<<`.

Мова бази — українська (назви папок, статусів і розділів). Якщо користувач хоче базу іншою мовою, перекласти назви папок, статусів, розділів шаблонів і запити Dataview на `00 Головна.md` і в `Журнал питань.md` узгоджено, а також відповідні назви в скілах.

## 3. Встановити скіли
Скопіювати папки з `skills/` у папку скілів агента. Для Claude Code — `~/.claude/skills/` (на Windows `C:\Users\<ім'я>\.claude\skills\`). Якщо скіли з такими іменами вже є — не перезаписувати мовчки: порівняти й запитати.

## 4. Прописати базу в CLAUDE.md робочої папки
У `CLAUDE.md` робочої папки користувача (створити, якщо немає) додати або доповнити розділ:

```markdown
## Бази знань QA

Вимоги, питання, рішення, тест-кейси й довідка зберігаються в базах знань (Obsidian, синхронізація з Git):
- <Проєкт> (<платформи>; задачі <КЛЮЧ>) — `<повний шлях до бази>`

Шукати там насамперед. Нові задачі й вимоги заводити туди через скіли `kb-intake`, `kb-testcases`, `kb-change`. Правила роботи з кожною базою — у її `CLAUDE.md`.
```

За цим розділом скіли обирають базу.

## 5. Git
У папці бази:
```bash
git init -b main
git config core.quotepath false
git add -A
git commit -m "Каркас бази знань QA"
```
Віддалений репозиторій створює користувач (порожній, Private, без README). Коли він дасть адресу — замінити `<<АДРЕСА_РЕПОЗИТОРІЮ>>` у `Налаштування.md`, закомітити й дати користувачу команди `git remote add origin …` і `git push -u origin main`. Якщо середовище не дозволяє агенту push — користувач виконує їх сам.

## 6. Obsidian
Провести користувача за `Налаштування.md` бази: встановлення Obsidian, «Відкрити папку як сховище», плагіни Dataview і Git, інтервал автосинхронізації 10 хвилин, Pull on startup. Відома проблема: кнопка «Огляд» у сторонніх плагінах іноді не натискається одразу після виходу з обмеженого режиму — допомагає перезапуск Obsidian.

Після налаштування перевірити за файлами:
- `.obsidian/community-plugins.json` містить `dataview` і `obsidian-git`;
- у `.obsidian/plugins/obsidian-git/data.json` `autoSaveInterval` = 10, `autoPullOnBoot` = true.

Через 10 хвилин перевірити, що автокоміт дійшов до віддаленого репозиторію (`git ls-remote origin main` збігається з `git rev-parse HEAD`).

## 7. Перша задача
Попросити користувача надіслати першу задачу й завести її скілом `kb-intake`. Для вивантаження з Jira (Export → Word) — `node scripts/jira-doc-to-text.js <файл.doc> <файл.txt>` із цього шаблону. Після — `bash scripts/check-links.sh <папка бази>`.

## Чого не робити
- Не класти в базу паролі, токени й коди.
- Не ставити «погоджено» без слів людини.
- Не видавати здогадку за факт: опосередкований висновок позначати «гіпотеза».
- Не публікувати базу й не робити репозиторій публічним без явного дозволу користувача.
