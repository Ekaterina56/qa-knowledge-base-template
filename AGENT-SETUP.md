# Инструкция для агента: развернуть базу знаний QA

Пользователь дал ссылку на этот репозиторий и попросил развернуть базу знаний для проекта. Действуй по шагам. Пиши пользователю на его языке (по умолчанию — по-русски).

## 0. Узнать у пользователя
Спросить одним сообщением, если это не сказано:
1. **Название проекта** (например «Shop App»).
2. **Ключ задач в трекере** (например `SHOP-`), если есть.
3. **Платформы**: одна или несколько (приложение, веб, админка, бэкенд…).
4. **Где хранить базу** — папка на компьютере. По умолчанию: рядом с рабочей папкой, `kb-<проект>`.
5. **Где будет удалённый репозиторий**: GitLab или GitHub (сам репозиторий создаёт пользователь).

Если продуктов несколько — по одной базе на продукт. Платформы одного продукта — одна база.

## 1. Скопировать каркас
- Склонировать этот репозиторий во временную папку (это скачивание: если правила среды требуют разрешения — спросить).
- Скопировать содержимое `vault/` в папку базы. Без `.git` шаблона.
- Временную копию шаблона удалить.

## 2. Заполнить заглушки
Во всех файлах базы заменить:

| Заглушка | На что |
|---|---|
| `<<ПРОЕКТ>>` | название проекта |
| `<<ПРИМЕР_ЗАДАЧИ>>` | пример ключа задачи, например `SHOP-123` |
| `<<ПАПКА_БАЗЫ>>` | полный путь к папке базы |
| `<<АДРЕС_РЕПОЗИТОРИЯ>>` | адрес удалённого репозитория, когда пользователь его даст; до этого оставить заглушку |

Платформы:
- **Несколько** — в `README.md` базы оставить таблицу значений `platform` и поправить её под продукт. В шаблонах `platform: []` оставить.
- **Одна** — в `README.md` и `CLAUDE.md` базы удалить разделы о платформах, на `00 Главная.md` удалить раздел «По платформам», из шаблонов — строку `platform: []` (и `device`, если не нужно).

Проверить, что заглушек не осталось: поиск по `<<`.

## 3. Установить скиллы
Скопировать папки из `skills/` в папку скиллов агента. Для Claude Code — `~/.claude/skills/` (на Windows `C:\Users\<имя>\.claude\skills\`). Если скиллы с такими именами уже есть — не перезаписывать молча: сравнить и спросить.

## 4. Прописать базу в CLAUDE.md рабочей папки
В `CLAUDE.md` рабочей папки пользователя (создать, если нет) добавить или дополнить раздел:

```markdown
## Базы знаний QA

Требования, вопросы, решения, тест-кейсы и справка хранятся в базах знаний (Obsidian, синхронизация с Git):
- <Проект> (<платформы>; задачи <КЛЮЧ>) — `<полный путь к базе>`

Искать там в первую очередь. Новые задачи и требования заводить туда через скиллы `kb-intake`, `kb-testcases`, `kb-change`. Правила работы с каждой базой — в её `CLAUDE.md`.
```

По этому разделу скиллы выбирают базу.

## 5. Git
В папке базы:
```bash
git init -b main
git config core.quotepath false
git add -A
git commit -m "Каркас базы знаний QA"
```
Удалённый репозиторий создаёт пользователь (пустой, Private, без README). Когда он даст адрес — заменить `<<АДРЕС_РЕПОЗИТОРИЯ>>` в `Настройка.md`, закоммитить и дать пользователю команды `git remote add origin …` и `git push -u origin main`. Если среда не разрешает агенту push — пользователь выполняет их сам.

## 6. Obsidian
Провести пользователя по `Настройка.md` базы: установка Obsidian, «Открыть папку как хранилище», плагины Dataview и Git, интервал автосинхронизации 10 минут, Pull on startup. Известная проблема: кнопка «Обзор» в сторонних плагинах иногда не нажимается сразу после выхода из ограниченного режима — помогает перезапуск Obsidian.

После настройки проверить по файлам:
- `.obsidian/community-plugins.json` содержит `dataview` и `obsidian-git`;
- в `.obsidian/plugins/obsidian-git/data.json` `autoSaveInterval` = 10, `autoPullOnBoot` = true.

Через 10 минут проверить, что автокоммит дошёл до удалённого репозитория (`git ls-remote origin main` совпадает с `git rev-parse HEAD`).

## 7. Первая задача
Попросить пользователя прислать первую задачу и завести её скиллом `kb-intake`. Для выгрузки из Jira (Export → Word) — `node scripts/jira-doc-to-text.js <файл.doc> <файл.txt>` из этого шаблона. После — `bash scripts/check-links.sh <папка базы>`.

## Чего не делать
- Не класть в базу пароли, токены и коды.
- Не ставить «согласовано» без слов человека.
- Не выдавать догадку за факт: косвенный вывод помечать «гипотеза».
- Не публиковать базу и не делать репозиторий публичным без явного разрешения пользователя.
